The Premise

Distributed autonomy is becoming the default for aerial systems.

A flock is not centrally choreographed. Each agent acts on local perception and simple rules; the global behaviour emerges. Reynolds formalised this in 1987 [1] and every modern aerial swarm builds on it.

Reynolds 1987 · boids·separation · alignment · cohesion·[1]

Vocabulary

Six terms that frame the rest of the deck.

01

Formation

The geometric pattern agents try to hold: line, V, circle, communication-aware, and others.

02

Path planning

The algorithm that chooses how to get from A to B: A*, Theta*, Dijkstra, BFS, and more.

03

Communication model

How agents exchange state and intent: V2V channel or a baseline legacy model.

04

Jamming

Active RF interference that degrades the comm channel, modeled as low_jam or high_jam.

05

Spoofing

Forged messages or positions: phantom, position-falsification, or coordinate shift.

06

Crypto-auth

Keyed message signatures (e.g. HMAC-SHA256) that let receivers reject tampered messages [9].

Reference architecture

Every swarm is
three layers.

Perception turns sensor and radio inputs into a model of self plus neighbours. Coordination applies local rules and formation control on top of that model. Action executes the chosen path.

Each layer is a separate attack surface (see slide 11) [3].

Paradigms · Where control lives
Act I · 07 / 32
Three paradigms

Where does the control live?

Centralised

Ground station plans for everyone.

Easy to optimise; brittle when comms drop. A single radio outage can stall the whole mission.

  • Single planning point
  • Optimal but fragile
Decentralised

Each agent decides from local neighbours.

Hard to prove optimal; degrades gracefully. Pure boid-style behaviours sit here [3].

  • Local rules only
  • Survives partial failures
Hybrid · used here

Thin centre, local autonomy.

High-level intent from a leader, low-level execution local. The pattern Swarm Squad implements [4].

  • Best of both
  • Most modern UAV systems

Where the design language came from

Birds, then code.

Biological

Local rules,
global flocks.

Reynolds' three rules (separation, alignment, cohesion) produce convincing flock motion with no leader at all [1].

Figure 2 · Reynolds' three local rules

Engineered (UAV)

Local rules,
plus mission.

Engineered swarms keep the local-interaction recipe but layer on path planning, formation modes, and explicit comm protocols so the swarm can actually go somewhere useful [4].

  • Formation + path planner + comm model
  • Heterogeneous payloads possible
  • Robust on purpose, by design
  • Cryptographic message integrity is opt-in

Threat model · Three concentric surfaces
Act II · 11 / 32
Threat model

Three nested surfaces
the adversary can hit.

Recent UAV cybersecurity surveys group attacks into a small number of repeating patterns. Three concentric surfaces describe most of them [5][6][8].

  • RF / Comm. Jam the channel, drop the link.
  • Perception. Spoof GPS, fake neighbours, forge messages.
  • Mission / control. Hijack waypoints, drain endurance, fork the swarm.

Act II · 12 / 32
Compare · Same scenario, two power levels

Jamming: low vs high.

Before · low_jam

Mild degradation.

Messages get retried or dropped occasionally. Formation holds; mission steps grow slowly. A useful baseline-contested condition.

→ destination still reached

After · high_jam

Severe degradation.

Link near-collapse inside the zone. Coordination breaks; agents fall behind. Where proactive routing or LLM rerouting earn their keep [5][6].

→ mission may fail or time out

Threat B · Three spoofing modes
Act II · 13 / 32
Spoofing

Three ways to lie to a swarm.

Civil GPS is unauthenticated by design. Humphreys' 2012 White Sands demonstration hijacked a real UAV with low-power counterfeit signals from half a mile away [7].

01 / phantom

Phantom agents

Inject fake agents (dashed). The swarm tries to make room for neighbours that aren't there.

02 / position_falsification

Position falsification

Random offsets on real positions. Formation control over-corrects against noise.

03 / coordinate

Coordinate shift

Same fake offset for all; the swarm drifts coherently. Hardest to spot visually.

Act II
Countermeasure · Cryptographic message authentication
Act II · 14 / 32
Compare · Same spoofer, different defence

Crypto OFF vs ON.

Before · Crypto OFF

Receiver trusts
whatever arrives.

Without keyed authentication, the swarm can't distinguish a forged message from a real one. Spoofed positions enter the control loop directly; detection_rate stays near zero.

  • FN (false negative) rate high
  • Mission outcome reflects the spoof
After · Crypto ON · hmac_sha256

Tampered messages
get rejected.

HMAC-SHA256 is the NIST FIPS 198-1 standard for keyed message authentication [9]. With a shared key, any modified or forged message fails verification. detection_rate typically jumps; tp and tn grow [8].

  • Spoofed packets → rejected counter
  • Crypto does not remove jamming (different layer)

Spoof-detection KPI

The four numbers behind detection_rate.

Every Attack Metrics panel reports a 2x2 confusion matrix (true vs false, positive vs negative) plus a derived detection_rate. The rubric weighs these numbers, not screenshots alone.

detection_rate = TP / (TP + FN)
The single ratio your rubric weighs most

Python · Six primitives that cover the assignment
Act III · 17 / 32
The whole list

Six primitives. You will use every one.

01 / IMPORT

Import

from swarm_squad_ep1.client import SwarmSquadClient

Pull the library in once at the top.

02 / VARIABLE

Variable assignment

client = SwarmSquadClient()

Store the object so you can call methods on it later.

03 / CALL

Function call

client.reset_simulation()

Parentheses mean "do it now". Empty parens are fine.

04 / KWARGS

Keyword arguments

add_jamming_zone(center=(12,45,10),
    radius=16, jam_type="low_jam")

Pass arguments by name; order does not matter.

05 / LIST & TUPLE

List & tuple

coords = (10.0, 45.0, 10.0)
scenarios = ["baseline", "low_jam"]

Tuples for fixed coords; lists for sequences.

06 / DICT

Dictionary read

attack = client.attack_metrics()
rate = attack["detection_rate"]

Methods return JSON-as-dict; read fields with brackets.

Control loop · How a scripted scenario flows
Act IV · 23 / 32
SwarmSquadClient lifecycle

Reset. Configure.
Start. Observe. Repeat.

Each scenario in student_assignment.py follows this four-step rhythm. The loop closes when the script picks up a new scenario row and calls reset_simulation() again.

  1. Reset. reset_simulation() + clear zones.
  2. Configure. Algorithm, zones, crypto, LLM.
  3. Start & observe. start_simulation(...) + poll simulation_state().
  4. Collect & next. attack_metrics() + protocol_stats(), then loop.

API · Six SwarmSquadClient calls students use most
Act IV · 24 / 32
High-leverage API

Six methods cover ~80% of Assignment 2.

01 · ALG

set_algorithm(...)

Switch formation + path planner mid-mission. Accepts formation, path_algorithm.

02 · JAM

add_jamming_zone(...)

Drop a circular jamming zone. center=(x,y,z), radius, jam_type, intensity.

03 · SPOOF

add_spoofing_zone(...)

Configure one of three modes plus magnitude / vector. Compose with jamming to study layered attacks.

04 · CRYPTO

set_crypto_auth(...)

Toggle keyed authentication + pick algorithm. The single most important defence knob.

05 · LLM

set_llm_assistance(...)

Enable LLM-driven rerouting when comm quality drops. Best paired with high-jam scenarios.

06 · METRICS

attack_metrics()

Returns the confusion-matrix dict (tp / fp / fn / tn / detection_rate), which is the rubric's evidence row.

Closing · The takeaway
31 / 32
Closing manifesto
"Build. Attack. Defend. Measure."

A swarm you cannot reproduce is a story. A swarm you can reproduce, and break, and fix, and measure, is research.

Takeaway 01

Change one variable at a time.

Both rubrics penalise scenarios that vary multiple knobs. Require a scenario matrix before the first run.

Takeaway 02

Numbers beat screenshots.

Make students paste attack_metrics() JSON next to every screenshot. Visuals describe what; metrics prove how much.

Takeaway 03

Crypto and jamming are different layers.

If a student claims HMAC stopped jamming, mark for re-read. Defences must be matched to the surface they actually protect.
